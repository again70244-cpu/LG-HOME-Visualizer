# LG-HOME-Visualizer

LG 家電空間預覽系統 — 把去背的商品圖，以**真實比例**合成進客戶家中的實際照片。

零依賴的靜態網站 / PWA，可安裝到手機或平板的主畫面，離線可用。
**所有影像處理都在瀏覽器本機完成，照片不會上傳到任何伺服器**（客戶家中照片屬個資）。

## 檔案結構

```
index.html            正式部署入口（完整文件，含 PWA 標頭）
preview.html          預覽入口（給會自帶 head 的環境用）
app.css / app.js      全部樣式與邏輯，兩個入口共用，不會有版本落差
manifest.webmanifest  PWA 資訊：名稱、圖示、standalone 顯示
sw.js                 Service Worker：離線快取
_headers              CSP 與快取標頭（Cloudflare Pages / Netlify 會讀）
fonts/ icons/         自架字體與圖示
```

## 隱私：不是承諾，是強制

客戶家中照片屬個人資料，所以這個專案的隱私保證是**結構性**的，不是靠自律：

1. **沒有後端。** 照片的路徑是「檔案選擇器 → 瀏覽器記憶體 → canvas → 輸出圖」，
   程式裡沒有任何 `fetch` / `XMLHttpRequest` / form 送出。
2. **字體自架。** 不連 Google Fonts，所以頁面載入完成後**不對外發出任何請求**。
3. **CSP `connect-src 'none'`。** 瀏覽器層級禁止這個頁面發出網路連線。就算未來
   程式出錯或被植入，上傳在技術上不可能發生。

驗證方式：**載入頁面後開飛航模式，工具照常運作。**
開發者工具的 Network 分頁也可以確認：除了本站自己的檔案，沒有任何請求。

Service Worker 需要抓自己的檔案建立離線快取，所以 `_headers` 只對 `/sw.js`
放行 `connect-src 'self'`；頁面本身仍然是 `'none'`。

### 不要把客戶照片 commit 進來

這個 repo 是公開的，照片一旦進版控就是永久公開，刪檔也還留在 git 歷史裡。
`.gitignore` 預設擋掉所有影像與影片格式，`icons/` 與 `fonts/` 兩個專案素材
資料夾例外放行。

副檔名用 `[jJ][pP][gG]` 這種字元類別展開，因為 gitignore 區分大小寫，
而 iPhone 的檔名預設是大寫（`IMG_1234.HEIC`、`IMG_1234.JPG`、`IMG_1234.MOV`）
—— 正好是最可能誤入版控的那一種。

需要版控測試素材時用 `git add -f` 個別加入，並先確認那不是真實客戶的家。

## 部署

靜態託管即可，不需要伺服器端執行環境。

**Cloudflare Pages（建議）** — 連上這個 repo，建置指令留空，輸出目錄設為根目錄。
會自動讀 `_headers`，所以 CSP 生效。

**Netlify** — 同樣會讀 `_headers`。

**GitHub Pages** — 可以跑，但**不支援自訂 HTTP 標頭**，所以 CSP 那一層不會生效
（前兩項保證仍然成立）。私有 repo 需要付費方案。

更新流程：推上分支 → 託管平台自動部署 → 使用者下次連線就是新版。
`sw.js` 對 HTML/CSS/JS 採網路優先，所以不會被舊快取卡住；字體與圖示才用快取優先。

## 使用流程

| 階段 | 內容 |
|---|---|
| 1 載入素材 | 上傳客戶空間照片 + 商品去背 PNG；自動由 EXIF 判讀鏡頭視角 |
| 2 真實比例校正 | 消失點自動校正（視平線＋牆面基準）、商品實際高度與深度、相機高度、鏡頭視角 |
| 3 擺放、轉向與透視 | 拖曳定位、水平轉向、尺寸微調、垂直透視、水平鏡射 |
| 4 光影與融合 | 場景預設、點選光源位置、地板材質；12 個細項收在「進階調整」 |
| 5 檢視與輸出 | 比對原圖、輸出原始解析度合成圖、一鍵全部重設（可復原）|

## 比例是怎麼算出來的

採用單視圖測量學（single-view metrology）。對任何站在地面上的物體：

```
畫面高度(px) = (物體底部y − 視平線y) × 實際高度 / 相機高度
```

只要校正好視平線與相機高度，把商品往畫面深處拖曳時尺寸會自動縮小，
比例永遠正確。狀態列會即時顯示推算出的實際尺寸、該位置的比例尺（px/cm），
以及「尺寸微調」偏離真實比例的百分比。

## 消失點校正

合成看起來「假」最主要的原因，是**商品的透視方向與房間的透視方向互相矛盾** —
兩個消失點同時出現在一張圖裡，大腦會立刻察覺，這比陰影或色調的影響都大。

在照片上拉兩條沿著地面、方向不同的線（例如左邊牆腳線與右邊女兒牆底線），
它們的交點就是地面的消失點，一次給出兩樣東西：

- **交點的 y** ＝ 正確的視平線高度。視平線設錯，商品會整個放大或縮小
- **交點的 x** ＝ 房間深度軸的方向：`牆面基準角 = atan((vp_x − cx) / f)`

套用後，轉向角變成**相對於牆面的偏移量**，0° 就是貼齊牆面方向，不會再轉錯邊。
校正期間商品會暫時隱藏，方便看清楚地面的邊。

## 轉向是怎麼做的

只有一張正面去背圖也能轉向。把商品視為長方體，即時投影：

```
s = 沿寬度(cm)  t = 沿深度(cm)  h = 離地高度(cm)  θ = 轉向角
z = z₀ − s·sinθ + t·cosθ
x = cx + f·(X₀ + s·cosθ + t·sinθ) / z
y = cy + f·(相機高 − h) / z
```

物體繞垂直軸旋轉、相機無翻滾時，**垂直線在畫面上仍然是垂直線**，
所以用「垂直條帶」渲染前面板與側面是精確投影，不是近似。
θ = 0 時本式退化成上一節的比例公式，行為完全一致。

- **前面板**：去背圖，逐條帶依透視縮放
- **側面**：從去背圖靠邊緣的像素欄擠出，所以顏色與商品一致；可調明暗
- **頂面**：商品低於相機高度時才繪製（例如 85cm 的洗衣機）

不採用 AI 生成側面：需要 API、有成本、每次結果不同，而且會竄改商品細節。
即時幾何運算是免費、即時、確定性的。側面僅作擺放示意，不保證與實機相同。

## 介面：預設優先

陰影與融合原本是 12 個滑桿，用的全是後製術語。但那 12 個值其實只在描述四件事，
所以簡易介面只問四個問題，進階調整預設收起來（一項都沒刪）：

| 使用者回答的問題 | 一次決定 |
|---|---|
| 拍攝時的光線像哪一種（陽台／室內燈／陰天／陽光直射） | 陰影長度、柔和度、濃度、接觸陰影濃度與範圍、曝光匹配、環境染色、雜訊 |
| 光從哪裡來（在照片上點窗戶或燈） | 陰影方向 |
| 地板材質（霧面／一般／亮面） | 地板倒影強度 |

光源存的是**位置**而不是角度，所以移動商品時陰影方向會自動跟著轉。
「自動偵測」取照片最亮 12% 像素的重心當光源位置。
手動動了進階裡的對應滑桿，該項的預設按鈕就會取消高亮，不會誤導。

## 一鍵重設

「全部重設」把所有調整回到預設值，但**保留已載入的照片，以及 EXIF 判讀出的鏡頭視角**
—— 視角是照片本身的屬性，不是使用者的調整，重設它只會製造新的錯誤。

不跳確認對話框（現場操作時是多餘的摩擦），改成直接重設並在訊息列提供「**復原**」，
14 秒內可以還原到重設前的完整狀態。

## 擬真度的關鍵

依效果由大到小：

1. **接觸陰影** — 物體與地面接觸處的深色暗影，是判斷「有沒有真的站在那裡」最主要的線索
2. **投射陰影** — 由 alpha 剪影經傾斜＋壓縮變形投影到地面
3. **正確比例與透視** — 見上節
4. **地板倒影** — 亮面地板（磁磚、拋光石英磚）適用
5. **曝光匹配** — 取樣商品落點周圍的環境，匹配亮度、黑階與對比。亮度與色度分開處理，中性色保持中性
6. **環境染色** — 另外的小幅度色偏，每通道上限 ±14，避免銀色機身被暖色地板染成米黃
7. **邊緣修整** — alpha 腐蝕，清除去背殘留的白邊
8. **雜訊匹配** — 讓過於乾淨的商品圖貼近照片本身的顆粒

## 行動裝置

- `manifest.webmanifest` + Service Worker → 可「加到主畫面」，全螢幕執行、離線可用
- 輸出時優先叫出**系統分享選單**（`navigator.share`）：一步存到相簿或傳給客戶，
  不支援的瀏覽器才退回長按另存
- 窄螢幕改用**底部面板**：畫布佔滿上方，控制項收進可上下拉的面板，
  三段檔位（74px 露出 / 46vh / 86vh），放開手指吸附到最近一段。
  面板高度寫進 `--sheet`，畫布區讓出同樣高度，**所以面板再高也不會蓋住畫布** ——
  改的是 CSS 顯示尺寸而非 canvas 點陣尺寸，不會觸發重繪
- 五個步驟改成**分頁**，一次只顯示一個，不用再從頭捲到尾
- 畫布支援**雙指縮放**（1–6 倍）與平移，用 CSS transform 實作；
  `getBoundingClientRect()` 本來就會把 transform 算進去，所以拖曳商品的座標換算不用改
- 手機版頁首壓成單行（170px → 43px），省下來的全部給畫布
- `@media (pointer:coarse)` 下所有滑桿、按鈕、拖曳控制點都放大到接近 44px；
  畫布上的命中範圍（視平線、消失點控制點、商品）同步放大 2.2 倍
- 數字輸入框在觸控裝置用 15px 以上，避免 iOS 自動放大頁面
- 商品照片的檔案選擇器**不加 `capture`**：加了會讓 iOS 只能拍照、不能從相簿選，
  反而更難用。預設行為本來就會同時提供「拍照 / 照片圖庫」

平板（尤其 iPad）是最適合的裝置：螢幕大，雙欄版面直接可用，觸控拖曳擺放比滑鼠直覺。

## 拍攝建議

合成品質有一半取決於拍攝。工具的投影模型假設**光軸水平、無翻滾**，所以：

- **手機保持完全垂直**，不仰不俯不歪（打開相機格線）
- **只用 1× 主鏡頭**，超廣角的桶狀變形會讓直線變弧線，長方體對不上
- **傳原檔**（AirDrop、雲端硬碟）。用 LINE、微信傳會移除 EXIF，鏡頭視角就得手動選
- **保持水平拍攝時，視平線就正好在畫面正中央 50%** — 光軸水平時地平面的消失線必定通過主點。前提是不裁切照片
- **畫面裡要有兩個方向的地面直線**（牆腳線、地磚縫、門檻），消失點校正才算得出來
- **擺放位置放在畫面中央三分之一**，鏡頭變形在四角最嚴重

### 鏡頭視角自動判讀

載入空間照時會直接解析 JPEG 的 EXIF（內建解析器，無外部依賴），
取 `FocalLengthIn35mmFilm`（0xA405）換算成本工具使用的「長邊視角」：

```
對角視角 = 2·atan(21.635 / f35)          21.635mm = 35mm 片幅對角線半長
f_px     = (√(W²+H²) / 2) / tan(對角視角 / 2)
長邊視角 = 2·atan((max(W,H) / 2) / f_px)
```

先走對角線再依實際長寬比換算，所以 4:3 與 16:9 都準確。
實測：等效 24mm（手機主鏡）→ 72°，等效 13mm（超廣角）→ 106°。

讀不到 EXIF 時會回到預設 75° 並提示手動選擇，不會沿用上一張照片的設定。
介面上會標示視角的來源是 EXIF 還是手動。

### 拍攝高度

相機高度直接決定比例換算，必須固定並記錄。量的是**鏡頭**到地面，不是螢幕中心
（直立持機時鏡頭比螢幕中心高約 5–7cm）。工具內建三組預設：

| 預設 | 高度 | 適用 | 頂面 |
|---|---|---|---|
| 站姿 | 145 cm | 衣物護理機 185 / 冰箱 179 / 洗乾衣機 170 | 不需推算 |
| 微蹲 | 115 cm | 空氣清淨機 100 | 少量 |
| 蹲姿 | 105 cm | 滾筒洗衣機 85 / 除濕機 60 | 盡量壓低 |

原則是**讓相機低於商品高度**，這樣就不必推算頂面 —— 頂面是整個模型裡最粗略的部分。
矮型家電無法避免看到頂面，蹲低可以讓它佔的面積變小。

預設值以身高約 168cm 的持機高度估算，請依實測調整。

## 限制

**側面是推算的，不是實拍。** 轉向後的側面由邊緣像素擠出，顏色正確、輪廓正確，
但不會有實機側面的散熱孔、接縫、標籤等細節。用於向客戶示意擺放位置沒問題；
需要精確呈現側面外觀時，仍應準備該角度的去背圖。

**長方體假設。** 非方正造型（圓筒狀清淨機、有明顯外凸把手的冰箱）轉向後誤差較大。

**去背圖品質**：長邊建議 1500px 以上，否則放大後會糊。
載入時會自動裁切到 alpha 邊界，所以圖檔四周留白不影響比例計算。

## 後續方向

- 手動遮罩：讓前景物件（沙發、櫃體）擋在商品前面
- 多角度去背圖：依轉向角自動切換最接近的實拍角度，取代推算側面
- 商品資料庫：預存型號、實際尺寸與多角度去背圖
- AI 影像融合（harmonization）：以 3D/2D 合成結果為結構基礎，只調整光線與色調而不改變商品外觀
